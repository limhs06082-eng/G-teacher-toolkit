# 수업·업무 도구함

수업 진행판·형성평가·업무 체크리스트·문구 템플릿을 **한 주소에서** 쓰는 교사용 웹앱입니다.
쌤동네 연수에서 만든 앱 4종을 하나로 합쳤습니다.

| 원래 앱 | 통합본 위치 |
|---|---|
| 수업 활동 진행판 | 수업 진행 |
| 형성평가·퀴즈 | 형성평가 |
| 회의·업무 체크리스트 | 업무 체크 |
| 문서·문구 템플릿 | 문구 템플릿 |

> 학급 운영(자리배치·역할당번·활동보상·과제제출)은 별도 저장소인
> **우리 반 — 학급 운영 통합 앱**에 있습니다. 그쪽은 학생 명단을 함께 쓰는 앱들이고,
> 이 저장소는 명단이 필요 없는 도구들입니다.

---

## 무엇이 좋아지나

- **주소 하나**: 앱 4개를 각각 배포하고 각각 즐겨찾기할 필요가 없습니다.
- **전자칠판 화면**: 수업 진행·형성평가에 `전자칠판` 버튼이 있어 새 창으로 크게 띄웁니다.
  3~8m 떨어진 뒷자리에서도 읽히는 크기로 그립니다.
- **학생 응답 받기**: 형성평가에서 QR과 6자 코드를 띄우면 학생이 모둠 단위로 답을 냅니다.
  이름을 받지 않으므로 개인정보가 생기지 않습니다.
  (학생 휴대폰으로 받으려면 Firebase를 붙여야 합니다. 붙이기 전에도 같은 브라우저에서 시험해 볼 수 있습니다.)
- **자동 백업**: 되돌리기 어려운 작업 직전마다 앱이 알아서 직전 상태를 남깁니다.
- **한 벌의 디자인**: 네 도구가 같은 버튼·같은 알림·같은 백업 화면을 씁니다.

## 시작하기

### 그냥 써 보기

바로 쓰면 됩니다. 처음 설정이 없습니다.

다만 **설정 → 학교 정보**에 학교·선생님·학년·반을 넣어 두시면
문구 템플릿의 `{학교}` `{학년}` `{반}` `{교사}` 자리가 자동으로 채워집니다.

### 내 저장소로 가져가기 (연수생용)

1. 이 저장소 오른쪽 위 **Fork**
2. [Vercel](https://vercel.com)에 GitHub 계정으로 로그인 → **Add New Project** → fork한 저장소 선택
3. 설정을 바꾸지 말고 그대로 **Deploy**

환경변수나 추가 설정이 **필요 없습니다.** 배포되면 바로 쓸 수 있습니다.

`vercel.json`의 `rewrites`는 지우지 마세요. 이 앱은 주소가 여러 개인 단일 페이지 앱이라,
`/quiz` 같은 주소에서 새로 고쳤을 때 서버가 `index.html`을 돌려줘야 합니다.
없으면 새로 고침마다 404가 납니다.

> **fork했다면 `src/shared/siblingApp.ts`의 주소를 자기 것으로 바꾸세요.**
> 이 저장소에는 만든 사람의 배포 주소가 들어 있습니다. 그대로 두면 헤더의
> 이동 버튼이 **내 앱이 아니라 만든 사람 앱으로** 갑니다.
> 안 쓸 거면 `''`로 비우면 버튼이 사라집니다.

두 앱(학급 운영 · 수업·업무 도구함)을 서로 잇는 방법은
[`docs/linking-two-apps.md`](docs/linking-two-apps.md)에 있습니다.

### AI 문장 다듬기 (선택)

문구 템플릿에서 문장을 다듬어 주는 기능입니다. **없어도 나머지는 전부 동작합니다.**

쓰시려면 [Google AI Studio](https://aistudio.google.com/apikey)에서 API 키를 발급받아
**설정 → 학교 정보 → Gemini API 키**에 넣으세요.
키는 **이 브라우저에만** 저장되고 백업 파일에도 들어가지 않습니다.

## 자료는 어디에 저장되나

**이 브라우저 안에만** 저장됩니다(localStorage). 서버로 보내지 않습니다.

그래서 이 두 가지를 꼭 기억해 주세요.

> - 브라우저 기록·캐시를 지우면 **만들어 둔 자료도 함께 사라집니다.**
> - 다른 기기(집 노트북, 교실 PC)에서는 자료가 보이지 않습니다.

**설정 → 백업·복원**에서 파일로 내려받아 두세요. 홈 화면에도 14일마다 백업을 권하는 알림이 뜹니다.
내려받은 파일은 같은 화면의 `백업 파일 가져오기`로 어느 기기에서든 되살릴 수 있습니다.

여러 기기에서 함께 쓰고 싶다면 Firebase를 붙이면 됩니다.
→ [`docs/firebase-guide.md`](docs/firebase-guide.md)

### 예전 앱을 쓰던 분

**설정 → 기존 앱에서 가져오기**에서 원본 4개 앱의 자료를 옮길 수 있습니다.
원본 앱을 쓰던 **같은 브라우저**에서 열어야 합니다.

- 지금 자료를 지우지 않고 **더합니다.** 두 번 눌러도 두 벌이 생기지 않습니다.
- **원본 자료는 지우지 않습니다.** 언제든 원래 앱으로 돌아갈 수 있습니다.
- 옮기면서 형식이 달라 확인이 필요한 곳은 비워 둡니다. 예를 들어 원본 객관식의
  정답 보기를 찾지 못하면 정답을 비워 두고, 진행 전 점검에서 "정답 보기를 골라 주세요"로
  알려 줍니다. 아무 보기나 정답으로 채워 두면 수업 중에 틀린 채점이 나가기 때문입니다.
- 퀴즈 **결과 기록은 옮기지 않습니다.** 원본은 개인 응답을, 통합본은 팀별 정답 수를 남겨
  숫자를 지어내야 하기 때문입니다. 문제 세트만 옮기고 기록은 새로 쌓습니다.

## 개발

```bash
npm install
npm run dev
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run verify` | 타입 검사 → 테스트 → 빌드. **커밋 전에 이것부터** |
| `npm test` | 테스트만 |
| `npm run build` | 배포용 빌드 |

### 구조

```
api/
└─ refine.ts     문장 다듬기 (Vercel 서버리스 함수)
src/
├─ app/          라우터·레이아웃·오류 격리
├─ shared/
│  ├─ domain/    네 도구의 자료 모델
│  ├─ storage/   저장·백업 (Firebase는 여기에 붙습니다)
│  ├─ state/     ToolkitDataProvider — 모든 저장이 여기를 거칩니다
│  └─ ui/        공통 컴포넌트와 디자인 토큰
└─ features/     lesson · quiz · task · message · home · settings
```

지켜야 할 세 가지입니다.

- **기능 코드는 localStorage를 직접 부르지 않습니다.** 전부 `useToolkit().update`를 거칩니다.
  Firebase를 붙일 때 이 경계 덕분에 화면 코드를 고치지 않아도 됩니다.
- **저장 키는 `teacher-toolkit:v1:` 접두사를 씁니다.** 원본 퀴즈 앱은 `settings` 같은
  일반 이름을 써서 같은 주소에 놓인 다른 앱과 자료를 덮어쓸 위험이 있었습니다.
- **필수 환경변수를 만들지 않습니다.** fork 직후 설정 없이 배포·동작해야 합니다.
  Gemini 키는 설정 화면에서 교사가 넣습니다.

`src/shared/ui`와 `src/shared/storage`는 학급 운영 통합 앱에서 **복사해 온 것**입니다.
두 저장소가 각각 fork되므로 패키지로 빼지 않았습니다. 고칠 일이 생기면 양쪽을 함께 손봐야 합니다.

설계 배경과 판단 근거는 [`docs/superpowers/specs/`](docs/superpowers/specs/)에 있습니다.
