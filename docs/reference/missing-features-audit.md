# 통합 과정에서 빠진 기능 점검

**점검일** 2026-08-15
**대상** `G-teacher-toolkit` (2단계, 원본 4개 앱)
**계기** `G-classroom-suite`에서 같은 검사로 여섯 가지가 나왔다. 여기도 다시 본다.

---

## 왜 다시 봤나

2026-08-14 점검에서 이 저장소는 **"깨끗하다"**로 끝났다.
미사용 필드가 `schemaVersion` 하나뿐이었고 그것은 저장 계층 전용이라 정상이다.

그런데 그 뒤 suite에서 찾은 것들은 **필드 검사로는 하나도 안 잡혔다.**

| suite에서 찾은 것 | 필드 검사가 놓친 이유 |
|---|---|
| `Assignment.description` | 추가 모달이 입력을 받으므로 "쓰이는 필드"로 보였다. 보여 주는 곳이 없었을 뿐 |
| `Submission.note` | `setNote`가 훅에 있어 이름이 코드에 있었다. 부르는 화면이 없었을 뿐 |
| `Assignment.status` | 같은 이유. `updateAssignment`가 있는데 부르는 곳이 없었다 |
| `ScoreGoal.startDate` | 저장·복원 코드가 읽으므로 이름이 있었다. 계산이 안 읽었을 뿐 |

**필드가 코드 어딘가에 나온다는 것과 그 값이 교사에게 쓸모가 된다는 것은 다르다.**
그래서 검사를 둘 더 만들어 다시 돌렸다.

1. **훅이 내주는데 아무 화면도 안 부르는 것** — `use*.ts`의 `...View` 멤버 중 다른 파일에서 `.이름`으로 한 번도 안 나오는 것
2. **저장은 되는데 읽는 곳이 없는 필드** — 화면·기능 코드에서 `이름:`으로 쓰기는 하는데 `.이름`으로 읽지 않는 것

두 검사 모두 도메인·저장 계층은 뺀다. 거기선 당연히 전부 읽고 쓴다.

---

## A. 훅에 있는데 화면이 없는 것

만들어 둔 기능인데 누를 방법이 없다. **화면만 붙이면 된다.**

| 기능 | 무엇이 안 되나 | 상태 |
|---|---|---|
| ~~`useQuiz.setTeams`~~ | 팀이 `1모둠~4모둠` 넷으로 고정이었다 | **완료 2026-08-15** |
| `useQuiz.renameSet` | 퀴즈 세트 이름을 만든 뒤 못 고친다 | 중간 |
| `useLesson.renameTemplate` | 수업 흐름 템플릿 이름을 만든 뒤 못 고친다 | 중간 |
| `useLesson.goTo` | 수업 중 특정 단계로 바로 못 간다. 앞뒤로만 옮긴다 | 낮음 — 만들지 않기를 권함 |

### A-1. 팀 고정이 왜 높은가

`useQuiz.ts:49`에 `DEFAULT_TEAMS = ['1모둠', '2모둠', '3모둠', '4모둠']`이 있고,
`startRun`이 언제나 이 값으로 시작한다. `setTeams`는 있지만 부르는 화면이 없다.

**모둠이 여섯인 학급은 두 모둠이 퀴즈에 참여할 수 없다.** 세 모둠이면 빈 팀이 하나 남는다.
학급마다 모둠 수가 다른 것이 보통이라, 이건 "있으면 좋은 것"이 아니라
**그 학급에서는 기능이 성립하지 않는 것**이다.

---

## B. 저장은 되는데 읽는 곳이 없는 것

| 필드 | 문제 | 상태 |
|---|---|---|
| ~~`QuizQuestion.timeLimitSec`~~ | 값은 들어오는데 세는 화면이 없었다 | **완료 2026-08-15** |
| `LessonTemplate.subject` · `QuizSet.subject` | **과목.** 입력할 곳도 보여 줄 곳도 없다 | 중간 |
| `LessonRun.startedAt` · `QuizRun.startedAt` | 시작 시각을 적기만 하고 안 쓴다 | 낮음 — 만들지 않기를 권함 |

### B-1. 제한 시간이 왜 높은가

`legacyImport.ts:230`이 원본 자료의 `timeLimit`을 읽어 `timeLimitSec`에 넣는다.

**원본을 옮겨 오는 코드가 이 값을 가져온다는 것은 원본에 문항 타이머가 있었다는 뜻이다.**
모델도 팩토리도 저장도 다 갖춰져 있는데 세는 화면만 없다.
원본에서 옮겨 온 교사는 자기가 정한 제한 시간이 사라진 것으로 본다.

`subject`도 같다 — `legacyImport.ts:180`·`244`가 옮겨 오는데 어디에도 안 나온다.

### B-2. 시작 시각은 왜 낮은가

`startedAt`은 기록해 두면 나중에 "이 수업 몇 분 걸렸나"를 보여 줄 수 있다.
지금 없어도 수업 진행에 지장이 없고, 화면에 숫자 하나를 더 얹는 값어치가
확실하지 않다. **없어도 되는 것을 만들지 않는다.**

## 2026-08-15에 고친 것

**모둠 설정.** `ToolkitData.quizTeams`에 저장하고 `startRun`이 그 값으로 시작한다.
모둠 구성은 한 학기 내내 거의 같아서 퀴즈를 시작할 때마다 묻지 않는다.

**진행 중에는 잠근다.** `correctTeamsByQuestion`이 팀을 이름으로 담기 때문에
도중에 이름을 바꾸면 앞 문제에서 맞힌 점수가 어느 모둠 것인지 알 수 없게 된다.
이름을 옮겨 붙이는 코드는 만들지 않았다 — 퀴즈 한 판은 십여 분이고,
**드문 일을 위한 코드는 틀려도 알아채지 못한다.**

**문항 제한 시간.** 전자칠판에서 센다. **교사가 시작한다** — 문제를 띄우자마자
세면 교사가 다 읽기도 전에 시간이 간다. 정답을 공개하면 멈추고,
문제를 넘기면 처음으로 돌아간다.

남은 시간을 `QuizRun`에 넣지 않았다. 0.2초마다 저장이 일어나고 그것이 다른
창에도 퍼진다. 새로 고치면 처음으로 돌아가는 것이 맞다.

## 점검에 쓴 방법

앞으로도 화면을 새로 만든 뒤에는 이 셋을 함께 돌린다.
새 화면이 생길 때마다 "모델에는 있는데 화면이 없는 것"이 드러난다.

1. **미사용 필드** — 인터페이스 필드 중 화면 코드에 이름이 아예 안 나오는 것
2. **미사용 훅 API** — `...View` 멤버 중 다른 파일이 `.이름`으로 안 부르는 것
3. **쓰기 전용 필드** — `이름:`으로 쓰지만 `.이름`으로 안 읽는 것

2번과 3번이 1번보다 늦게 만들어진 이유가 이 문서의 첫 절에 있다.
**1번만으로는 "깨끗하다"는 잘못된 답이 나온다.**
